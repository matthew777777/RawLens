# RawLens 2.3.43

**Lucas–Kanade Reloaded merging is almost ready!** This release is a big step towards faster, cleaner burst super-resolution on your phone.

Changes since **2.2.86**.

## New Lucas–Kanade Reloaded — designed for mobile GPUs

The new **LK-SR** engine brings Lucas–Kanade Reloaded merging to a lighter,
mobile-focused implementation, with faster processing, robust motion handling
and cleaner reconstruction.

- **Up to around 3× faster than the previous LK-R engine in measured mobile
  runs.** An eight-frame full-resolution burst on Mali-G615 took **19.7 seconds
  instead of 52.9 seconds at 1×**, and **48.0 instead of 120.7 seconds at 2×**.
  Performance varies with device, scene and output resolution.
- **Robust motion handling with fewer reconstruction artefacts.** Reference-guide
  rejection protects moving subjects while retaining static detail. Revised
  reconstruction and chroma handling reduce checker/colour-maze artefacts,
  repeating-pattern colour bands and edge zipper.
- **Automatic KernelNet denoising based on PhotonCamera, on by default.**
  Low-noise scenes skip inference and denoising; strength rises automatically in
  noisier, low-light scenes. The app has an on/off switch and preserves saved off
  choices. The noise gate is inactive at or below 4% relative mid-grey noise and
  reaches full strength at 8%; it follows measured noise, not time of day.
- Support **up to 30 frames in 2× LK-SR modes**, subject to capture capacity and
  memory limits; native-scale LK-SR retains its 59-frame ceiling.
- Fix developed JPEG/JXL engine suffixes and consistently identify LK-SR in
  preparation, saving and error messages. Add explicit desktop DCT prior controls
  and report prior timing/call counts.
- **Less waiting on the first merge.** Vulkan pipelines prewarm in the background
  when LK-SR is selected.
- Retain native sharpness selection, learned sensor-noise models, staged RAW
  buffers and independent framing/output-resolution controls.

The engine is now integrated into the app as **LK-SR**. Work continues on image
quality and device coverage as it approaches release readiness.

## Faster KB-SR, with more control

**KB-SR** also gets a substantial mobile performance upgrade, alongside new
tuning and improvements to 2× reconstruction.

- **Full-resolution eight-frame processing fell from 27.7 seconds to around
  9 seconds** in the recorded Mali-G615 optimization series, using GPU-resident
  pyramid processing, fused work and faster KernelNet execution. These figures
  describe the tested workload.
- Add **KB-SR Lab** tuning and a **2× super-resolution** switch.
- Refine 2× KernelNet behaviour for sharper detail and reduce red/blue edge zipper
  while retaining the green reconstruction.
- Estimate scene noise when desktop input DNGs lack a `NoiseProfile`, and add the
  `tools/sr-pipeline/run.sh` launcher.
- Further reduce **tile seams, boxy contours and colour zipper** in KernelNet
  reconstruction. Weakly constrained flow is regularized and a continuous motion
  field is shared by reconstruction and rejection; continuous S.3 membership
  retains full rejection where motion membership is complete.
- Bring desktop Vulkan KernelNet colour-difference correction in line with the
  app, using valid DNG white balance automatically. Fix the CLI parser and support
  explicit `auto`, `off` and manual gains. Preserve reference Wronski/CPU defaults.
  These changes improve the tested scenes; complete artifact elimination across
  all scenes and devices is not established.

## Easier burst merging

- Give **KB-SR** and **LK-SR** a dedicated Merge settings tab; HDR+ remains a
  separate engine.
- Default offline merge development to **JPEG**, expose output-quality controls
  and support sharing captured bursts.
- Preserve device orientation for staged takes and correct desktop output
  orientation and CUDA-style rounding parity.
- Include standalone Lite tools and research controls for hybrid merging,
  fp16 frames, rejection and denoising experiments.

## Photo rendering and colour

- Add a per-lens **Basic | AgX** tone-mapper selector. AgX remains the default;
  switching to Basic preserves stored AgX settings.
- Match Basic across saved photos, offline merges, RAW previews, BGU previews,
  scopes and adaptive development metering. Integrate the curve in existing
  render passes, including fused AMaZE output, with sRGB/Display P3 and existing
  gainmap/PQ handling.
- Preserve bright cloud/highlight structure with a Basic highlight shoulder,
  matching the display response across CPU/GPU/BGU paths. Describe saved tone
  mapping in JPEG metadata.
- Add **two-radius chroma cleanup** to ordinary and merged development.
- Fix defringe stripping blue/purple colour from flat regions with zero green;
  retain purple-fringe suppression on genuine contrast edges.
- Improve histogram-posterior RAW white-balance fallback and transport lens
  shading for root RAW captures and merged DNGs.
- Correct stale PROGRAM AE test expectations to use the selected adaptive
  profile, including exposure compensation. This is a regression-test correction,
  not a new production exposure algorithm.

## Experimental lapis 200→50 MP capture

- Add a root-only **200→50 MP** one-shot mode for the supported Redmi Note 15 Pro
  (lapis) firmware. Capture the 200 MP block-CFA sensor readout, demosaic it with
  tiled Vulkan processing, then downsample to an **8160×6120 LinearRaw DNG**.
- Support development through the shared photo-output tail, with capture-time
  exposure, white balance, focus and orientation snapshots.
- Restore the sensor and restart preview before background conversion finishes.
  Vendor patches are firmware/hash checked and camera properties are restored
  through the worker lease/watchdog path.
- Include capture probes, conversion prototypes, calibration comparisons,
  shader sources/SPIR-V and development instrumentation tests.
- This mode remains experimental, requires active root and the supported
  firmware, and uses a normal 12.5 MP preview. Burst, HDR merging and ZSL are
  unavailable in this mode. Recorded full-frame GPU conversion took about
  40 seconds on Mali-G615; capture/restarts and DNG writing add time. Colour-chart
  calibration and a controlled detail comparison with vendor 50 MP remain open.

## Autofocus and two-exposure RAW HDR

- Recover silent continuous AF in RAW-only sessions independently of AE/AWB.
  Add a bounded preview trial and one supported continuous-picture retry for
  abandoned AUTO/MACRO tap scans. A retry must receive a real locked verdict;
  it can extend the worst-case tap timeout to seven seconds. Optical behaviour
  on the reported phones still needs device validation.
- Extend **two-exposure RAW HDR** to lenses supporting manual RAW capture and
  rooted lapis **DCG14**. DCG14 retains AE, meters the two exposures separately
  and accounts for delivered ISO/shutter differences and sensor storage levels.
  This remains a sequential, unaligned capture; keep camera and scene still.
- Rename the denoising/sharpening settings page to **Details**.

## Video, preview and interface

- Add gyro stabilization v2 with **L1 path smoothing** and self-calibration ( Work in progress for now )
- Reduce Encoded Video preview processing to the viewfinder budget while
  retaining the selected demosaic method.
- Pause the camera while Settings is open and clarify engine/preview controls.
- Keep every update-dialog action accessible on narrow displays.

## Documentation and developer tools

- Shorten the README, move detailed instructions into focused guides and rewrite
  the user guide for the current controls. Remove obsolete screenshots and
  distinguish historical performance evidence from current integration.
- Add RAW viewfinder/ISP GPU audits, MFSR parity explanations, tuning sweeps,
  synthetic bursts and full-resolution denoise/GALOSH comparison prototypes.
  Research experiments and opt-in controls do not establish shipped defaults.
- Document Basic rendering, device-profile findings, upstream comparison code
  and licensing. Ignore the generated `output/` directory.


## Validation

- Final app housekeeping run: GitHub debug unit suite and Android native build
  passed with `-PfreezeVersion`. **2,021 tests, 9 skipped, 0 failures and 0 errors**.
- SR module: **266 tests, 190 executed and 76 skipped, zero failures/errors**,
  including actual Vulkan reconstruction/rejection, motion-field and CLI checks.
- Six standalone KernelNet Vulkan cases at 1×/2× passed. Low-noise output was
  byte-identical with no extra GPU submissions; 6%/10% noise ran the extra pass
  and reduced synthetic flat-field variance. This is not a full-scene quality or
  low-light runtime guarantee.
- Earlier rendering work records Halide parity and isolated phone validation;
  lapis records a full 200→50 MP JPEG+DNG output/restoration acceptance run.
  The new KB-SR continuous-motion follow-up and autofocus optical behaviour have
  not been validated on Android hardware in this housekeeping run.
- The release remains a draft. Packaging, signing and installation are separate
  release steps; no new binaries are attached by this housekeeping task.
