# sr-vulkan 1:1 parity contract

`tools/sr-vulkan` is the unified SR merging library: the phone's exact SR
core plus the Vulkan compute backend shared by Android (NDK) and desktop
(Linux/macOS). "1:1" is enforced mechanically, not by review:

    python3 tools/parity_sr_vulkan.py        # standalone
    ./gradlew :tools:sr-vulkan:check        # runs parityCheck + tests

## What is byte-identical (39 files)

Every file below diffs EMPTY against its original (`diff` must print
nothing). The host-shim layer makes this possible: tiny desktop-only sources
in the `android.*`/`androidx.*` packages (`Log`, `SystemClock`, `Build`,
`GLES30` readback surface, `Context`/`AssetManager`, `Location`,
`ExifInterface`) expose the exact API surface the ported code uses, so no
ported line — not even imports — changes. Shims live only in this module and
never ship on Android.

- `com.matthew.rawlens`: all 17 pure `RawSr*` files + `RawSrMergeJob`,
  `RawSrKernelNetAniso`, `MosaicSrReconstructor`, both DNG writers,
  `RawPreDemosaicPipeline`, `GpsLocation`, `RawSensorUnpacker`,
  `DngNoiseProfile`, `DenoiseSettings`, `RawSuperResolutionSettings`,
  `QuadBayerPreparation`, `CaptureFileNames`, `RawBayerLayout`
- `com.matthew.rawlens` unified Vulkan backend (shared phone/desktop
  bytes; the app compiles the same files): `VkRawSrProcessor.kt`,
  `VkCompute.kt`, `SrVulkan.kt`, `RawSrGpuOutput.kt`, `UploadBuffers.kt`,
  `GpuRawAmazeInput.kt`
- `com.particlesdevs...ml`: `KernelNetNcnnProcessor.java` (identical;
  desktop loads the host `ncnnMl` library instead of the APK one)
- Resources: all of `shaders/` and both KernelNet model files

(The `com.matthew.burstrecon` helpers — `BayerCoords`, `DngAdmission`,
`BurstManifestFrame` — are desktop-owned now that their original module
is deleted; they carry no parity anchor.)

## Verbatim lifts (parity-checked regions)

Pure declarations lifted out of host-coupled files; the parity script diffs
the `LIFT-BEGIN..LIFT-END` body against the original line range:

- `RawNindPack.kt` ← `RawNindDenoiser.kt:13-137`

(The former `GpuRawAmazeInput`/`UploadBuffers`/`RawSrGpuOutput` lifts are
full shared files now — see above.)

## Unified Vulkan backend (no generator)

The GLES SR orchestrator is retired (deleted, with its port script): the
app and desktop compile the same six backend files above, enforced by the
parity script's empty-diff entries plus `check_retirement` (fails if the
old file/script reappears, if any source names the retired orchestrator,
or if a GL host token leaks into the backend — `GLES30` *constants* stay
as format tokens). Two platform seams exist, both explicit in shared
lines (no per-platform code):

- Dispatch slicing: `VkBound.dispatch` runs the retired GLES schedule
  (`RawSrGpuScheduling.slices`, per-slice fence, 1ms yield) with the
  phone's budgets by default (64 for block_match/lk_refine, else
  131072). Desktop launch paths set `-Dsrvk.sliceBudget=<huge>` for one
  full-grid slice per pass; omitting the flag exercises the phone's
  exact schedule on desktop (proven bitwise-identical on a 1024px
  burst crop).
- Shader loading: `VkProgramCache` reads `spirv/*.spv` + `manifest.json`
  through the platform `AssetManager` (APK assets on Android; staged
  directory with classpath fallback on desktop).

The app packages checked-in SPIR-V (`app/src/main/assets/spirv/`,
regenerated by the same transform); `:tools:sr-vulkan:spirvCheck` fails
the build if a fresh canonical-glslang transform disagrees (skips loudly
without the canonical toolchain).

## Allowlisted deviations (the complete list)

1. `RawFrameMetadata.kt`: imports + `RawFrameMetadataFactory.capture`
   (Camera2) replaced by `fromDng` (DNG tags → identical value, including
   the CFA-phase derivation and the row/column-major matrix transpose).
   Lines 16-104 of the original are range-checked verbatim.
2. `MosaicSrDngSaver.kt`, `LinearRgbDngSaver.kt`: desktop counterparts
   (same API shape, temp-file + atomic rename instead of MediaStore).
3. Shaders: sources stay ESSL and byte-identical; the checked-in
   `tools/srvk_shader_transform.py` maps them to Vulkan GLSL at build time
   (`#version 450`, explicit descriptor bindings, one std140 uniform block,
   same `#import` replication as `ProgramCache`). All 22 SR shaders compile
   to SPIR-V (`--target-env vulkan1.2`); the emitted manifest is the binding
   contract the Vulkan host implements. This is the single sanctioned
   shader transform — Vulkan cannot consume ESSL program objects.

## Deliberately not ported

- `Gles31AmazeProcessor` (EGL context, GL program cache, GL textures):
  stays for the single-frame AMaZE and develop paths, which remain GLES
  by design. The unified Vulkan backend (`src/main/cpp` + `VkCompute.kt`)
  supersedes it for SR merging on both platforms.
- `Gles31RawSrProcessor`: deleted by the cutover (with its port script);
  `VkRawSrProcessor.kt` is the shared orchestrator now.
- `RawSrDebugExporter`: instrumented-test-only peer; no merge path uses it.
- JPEG/develop/post paths (`RawDevelopmentCoordinator`, `Gles31*Develop*`,
  `JpegSaver`, viewfinder, video, HDR, dual-raw): outside SR merge scope.
  (The merged-JPEG save bridges Vulkan images back to GL textures in the
  coordinator; the develop engine itself is untouched.)
